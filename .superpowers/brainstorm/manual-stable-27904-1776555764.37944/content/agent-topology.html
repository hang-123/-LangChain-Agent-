研究增强型 Job Assistant 的 Agent Topology

这版不是把流水线硬改名，而是把系统拆成“调度中枢 + 领域 Agent + 证据与产物总线 + 审核层”。`job-assistant` 会从“单纯 specs 集合”升级成真正的多 Agent 业务域。

Entry

User Request

用户输入简历、目标岗位 / 公司、可选 JD、投递状态、补充偏好。

Coordinator

SupervisorAgent

识别意图、决定工作流、分派任务、收集产物、组装最终响应。

Guardrail

VerifierAgent

审查事实 / 推断 / 建议边界，检查证据覆盖、冲突、时效和降级条件。

Candidate Domain

ProfileAgent

从简历与用户补充输入中提取 `CandidateProfile` 和 `ResumeEvidence`。

Job Domain

JobIntelligenceAgent

融合 `raw_jd_text` 与现有 Search / Query / Insight 能力，产出岗位事实和外部证据包。

Decision Domain

MatchingAgent

基于候选人证据与岗位要求生成 `MatchAssessment`，解释优势、差距与风险。

Delivery Domain

ResumeTailorAgent

把匹配分析转成 `ResumeTailoringPlan` 和 `ResumeVersion`，但不能越过事实边界。

Delivery Domain

InterviewCoachAgent

输出 `InterviewPrepPack`，问题与追问必须绑定候选人证据和岗位证据。

Ops Domain

ApplicationOpsAgent

负责投递记录、状态推进、下一步提醒和幂等写入。

现有 `IntentRouter -> Search -> Query -> Insight -> Report/Review` 不再是产品主线，而是收编进 `JobIntelligenceAgent` 内部，变成岗位证据增强子系统。

Key Shift

Agent-like by Design

Agent 之间不直接传大段 prompt，而是通过 artifact 契约协作；Supervisor 负责编排，Verifier 负责放行。

`job-assistant` 需要同步升级的文档边界
  • `00-product-prd.md`：从“用户上传简历 + 粘贴 JD”扩展为“用户输入 + 外部岗位证据增强”。
  • `02-domain-model.md`：新增 `ExternalEvidencePack`、可能还要补 `TaskPlan / VerificationReport`。
  • `10-supervisor-agent.md`：从简单路由器升级成真正的多 Agent 编排中枢。
  • `12-jd-analyst-agent.md`：建议演进为 `JobIntelligenceAgent`，把外部检索与 JD 解析合并成岗位侧事实层。
  • `16-workflow-agent.md`：要体现 artifact 驱动、可恢复、可审计的多 Agent 工作流。
  • 可能新增 `17-verifier-agent.md`：专门定义审核和降级规则。
