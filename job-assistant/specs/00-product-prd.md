# 求职助手 PRD

## 1. 产品名称
Job Assistant

## 2. 产品目标
帮助求职者更高效地完成以下任务：
1. 理解自身优势与岗位要求的匹配程度
2. 结合真实 JD、公司画像和面经信号做更稳健的岗位判断
3. 针对目标岗位优化简历
4. 在后续阶段扩展到面试准备与投递流程管理

## 3. 目标用户
- 校招生

## 4. 当前阶段定义
本产品按两个阶段推进：

### 阶段一：当前交付范围
围绕 `岗位理解 -> 匹配分析 -> 简历定制 -> 基础事实校验` 建立一个可运行、可验证的小闭环。

### 阶段二：后续扩展范围
在阶段一稳定后，再扩展：
- 面试准备包
- 投递状态管理
- 完整的简历/JD 解析流水线
- 更独立的 Supervisor / Workflow / Verifier 体系

## 5. 核心场景
### 场景 A：岗位匹配分析（阶段一）
用户提供结构化候选人信息与目标岗位信息，系统输出：
- 匹配分数
- 优势
- 差距
- 风险提示
- 是否建议投递
- 岗位侧证据摘要（真实 JD / 公司画像 / 面经）

### 场景 B：简历定制（阶段一）
用户选择目标岗位，系统输出：
- 针对岗位的简历摘要
- 项目描述优化建议
- 关键词覆盖建议
- 基础事实校验结果

### 场景 C：面试准备（阶段二）
系统基于简历和 JD 输出：
- 高频面试题
- 示例回答框架
- 追问点
- 风险问题

### 场景 D：投递管理（阶段二）
系统记录：
- 已投递岗位
- 当前状态
- 下一步动作
- 跟进提醒建议

## 6. 非目标
当前版本不负责：
- 自动代投
- 编造项目经历
- 承诺 offer 概率
- 替用户作出最终职业选择
- 自动抓取所有招聘平台并大规模海投
- 自动生成最终排版好的 PDF / Word 简历模板

## 7. 成功指标
- 岗位匹配分析可解释且稳定
- 简历改写不虚构事实
- 用户能在 5 分钟内完成一次“候选人信息 + 目标岗位”的完整分析
- 用户认可输出结果“有帮助”的比例 > 70%

## 8. 核心约束
- 不允许虚构用户经历
- 不允许伪造数字成果
- 必须区分事实、推断、建议
- 信息不足时必须明确说“不足以判断”
- 岗位侧证据不得回写为候选人事实

## 9. MVP 范围
### 阶段一包含
- 结构化候选人输入接入（`CandidateProfile`、`ResumeEvidence`）
- 结构化岗位输入接入（`raw_jd_text` 可选，允许直接消费岗位侧证据）
- 外部岗位证据增强（真实 JD、公司画像、面经线索）
- 岗位匹配
- 简历优化建议
- 结构化简历版本产物
- 基础事实校验

### 阶段一不包含
- 完整简历解析上传链路作为主入口
- 完整 JD Parser 作为主入口依赖
- 基础面试准备
- 投递状态记录

### 阶段二规划
- 简历解析
- JD 解析
- 面试准备
- 投递状态记录
- 更完整的工作流编排与恢复
