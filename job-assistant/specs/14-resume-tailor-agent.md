# Resume Tailor Agent 规范

## 1. 目标
在不虚构事实的前提下，把候选人已有经历重新组织为更贴合目标岗位的简历版本。

说明：这是阶段一当前主链中的核心能力之一。当前阶段输出的是结构化 `ResumeTailoringPlan` 与 `ResumeVersion`，而不是最终排版好的简历文件。

## 2. 职责
- 基于匹配结果制定改写计划。
- 输出摘要建议、项目改写建议、关键词覆盖建议。
- 生成可审计的岗位定制简历版本。

## 3. 输入
```json
{
  "candidate_profile": {},
  "resume_evidence": [],
  "job_snapshot": {},
  "match_assessment": {}
}
```

## 4. 输出
```json
{
  "tailor_plan": {},
  "resume_version": {},
  "fact_check_report": {
    "status": "passed",
    "blocked_claims": []
  }
}
```

## 5. 改写策略
- 优先强化与高权重 `must_have` 相关的真实经历。
- 允许重排表达顺序，不允许新增未发生的事实。
- 允许把原始项目描述改得更聚焦，但必须保留原意。
- 可通过 `job_snapshot` 中的岗位要求和证据质量信息调整表达重心与关键词优先级，但不得把岗位证据伪装成候选人事实。
- 对缺失要求输出“补充建议”，而不是偷偷补写。

## 6. 输出质量要求
- 每条改写建议都应对应至少一个 `allowed_evidence_ref`。
- 缺失关键词时，可以建议补充表达，但不能把“会”改成“精通”。
- 最终 `ResumeVersion` 必须保留事实校验状态。
- 若当前仅生成结构化版本产物，也要保证字段可审计、可追溯，便于后续渲染到具体模板。

## 7. 禁止事项
- 不得编造数字成果、用户角色、项目规模。
- 不得把课程作业改写成实习经历。
- 不得承诺“这样改一定过筛”。
